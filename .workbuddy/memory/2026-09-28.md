## 头部识别准确性重做（用户反馈「摇头和抬头经常识别错误」）

### 查出的 4 个根因（都是设计层面错，不是调参）

1. **控制量用「画面比例」而不是「人脸尺度」**
   `raw = deadzone(cx - ncx, 0.06, 0.22)` —— 0.06/0.22 是*画面宽*的比例。
   人脸框只占画面宽 0.12~0.25，于是**灵敏度随坐姿远近翻倍变化**：
   坐近太灵、坐远推不动。用户感知就是"识别错误"。
   → 改成除以当帧脸宽/脸高（`DEADZONE_FACE=0.26 / FULL_SCALE_FACE=1.15`）。
   测试断言：同一物理位移在脸宽 0.30/0.20/0.12 下输出**完全一致**（极差 0）。

2. **`st.pitch`（关键点算出的真实俯仰）被完全丢弃**
   YuNet 已经用鼻尖/眼线/嘴线算出了尺度无关的 pitch，但控制器只用脸框中心的
   cy 位移 —— 而 cy 同时受前后移动、坐姿下滑、耸肩影响。→ 这是"抬头误判"主因。
   → 抬头以 pitch 为主；**动作键只认单一来源（pitch），绝不用融合值**。

3. **`st.yaw` 也没进 axis** —— 转头时脸框中心几乎不动（侧脸还会让框收缩、
   中心反向偏），所以"摇头"根本不产生控制量。→ 平移与摇头做**软最大融合**。

4. **校准基线被采歪 + 门限耦合**
   真机实测：校准那 1.3 秒里用户在看终端（yaw 采到 +0.53），之后转回屏幕
   （真实 yaw≈0），基线偏差一直扣 → **轴量停在 -0.26 不动**。
   而且自适应门限是几个通道共用的，俯仰偏离 0.75 时**横向基线的收敛被一起卡死**。
   → 加长窗口 + MAD 离群剔除 + **逐通道独立门限** + 校准后 8 秒用快时间常数。
   真机复测：基线 yaw 0.53 → 0.19，轴量全程 +0.00。

### 灵敏度按真机实测标定（不是拍的）
`yaw ≈ 2.14·sin(转头角)`（鼻尖横向位移 0.45·脸宽·sinθ 除以半眼距 0.21·脸宽）：
- 转头 12° → yaw ≈ 0.44，转头 30° → yaw ≈ 1.07
- 第一版满速取 0.50（≈12°）→ 真机上轻轻一偏头轴量就 **-0.98**。
  **"太灵"和"不灵"一样会被感知成"识别错误"。**
- 改成 死区 0.24（≈6°）/ 满速 1.10（≈30°）：4°→0、19°→0.53、41°→1.0

### 转向会顶起俯仰读数（真机实测耦合 0.32/0.43 ≈ 0.74）
2D 关键点在侧脸时往眼线方向漂移。**没有**做"按 yaw 减掉耦合量"的补偿 ——
耦合的符号和大小只能从极少样本推断，猜错会把真实抬头信号一起削掉（错误方向更糟）。
改成按转向幅度**衰减俯仰置信度**（`PITCH_YAW_SHRINK=0.75`，上限 0.60）：
不依赖符号，且失效方向安全（"转着头时抬头没反应" ≫ "一转头发动机就跳"）。

### 顺手抓到的真 bug
`_adapt` 里的冷却条件写成 `self._jump_t < 0.2`（已按住时长），而从没按过时恒为 0
→ 条件恒成立 → 每帧提前返回 → **整个中性位自适应是空操作**。
本意是"松开动作键后冷却"，应该用 `_gap_t`（距上次松开的时长，初值 99）。
**这个 bug 正是"校准歪了却永远回不到中位"的原因。**

### 验证方式（这类"手感"问题必须用行为断言）
新增 `tools/test_head.py`：**47 项断言，全通过**。覆盖：
距离无关性 / 摇头与平移两路 / 灵敏度三档标定 / 抬头触发 / 后靠不误触 /
阈值抖动不连发 / 尺度骤变保护 / 静止假阳性持续挡住 / 漂移被吸收 /
失检语义回归 / 姿态不可信降级 / 歪头不污染 yaw 与 pitch / 方向约定 /
基线自愈 / 逐通道独立 / 配置引用静态检查。

真机 `main.py --probe` 也会打印各路原始信号，并在基线偏离大时给出 ⚠ 提示。

## 修「头没动，大厅却一直左右选游戏」（用户反馈）

### 根因：小基线做差算出的量，信噪比天生极低
摇头 = 鼻尖相对双眼中点的位移 ÷ **半眼距**，而人脸检测只用 320 宽的缩略图：
```
脸宽 ≈ 64px   眼距 ≈ 27px   **半眼距只有 13px**
→ 鼻尖抖动 1px = yaw 噪声 0.07；3px = 0.22（正好等于死区）
```
**摇头在接进横向控制之前这点噪声无害；上一轮把它接进 axis 之后，噪声就直接
变成了控制量。** 上一轮 47 项测试全用干净合成信号，所以完全没抓到 ——
**噪声必须进测试**，这是本轮最重要的教训。

### 三条修法（各修一层，缺一不可）
1. **摇头路径单独重低通** `YAW_TAU=0.20s`。平移那一路量 64px 尺度的位移，
   信噪比高得多，`HEAD_TAU=0.075` 够用；"小基线做差"的量必须重滤波。
2. **死区带迟滞** `AXIS_EXIT=0.72`。信号停在死区边界时噪声会让它反复进出，
   已在"有控制"状态时用更低退出阈值就能钉住。
3. **起振门限** `AXIS_ARM=0.09s`。从静止进入有控制必须持续够久，单帧尖峰
   一律丢掉 —— 它永远不会变成让角色动一下、或让大厅跳一格的输出。
4. 大厅再加一道：方向必须**持续** `MENU_SWITCH_HOLD=0.10s` 才切。

### 修的过程中自己引入的回归（被测试抓到）
把**低通值**喂给自适应门限 → 形成反馈环：滤波值从 0 缓慢上升、一开始总小于
门限 → 基线在起振阶段就开始吸收这次转头，基线一动差值更小，环锁死。
实测"持续转头 4 秒后输出衰减到 0.03"（玩家会以为"转一会儿就没反应了"）。
**门限必须判原始读数，不能判滤波值。** 这是"滤波 + 反馈 + 阈值"组合的经典坑。

### 另外两个
- `Menu.__init__` 漏了 `_dir/_dir_t` 初始化（只在 `reset()` 里加了）→ 第一帧崩。
  **`__init__` 不会自动调用 `reset()`，新增状态字段要两边都加。**
- `MENU_DWELL` 2.4s → 3.6s：站着看一眼有哪些游戏，2.4 秒太短。

### 验证（新增 4 组 17 项，总计 64 项）
- σ=0.15/0.18/0.28 各档噪声：轴量翻转 **0 次**、越界 **0 帧**
- 端到端串「控制器 + 大厅」：静止 10 秒选中项变化 **0 次**；持续摇头 8 秒变 13 次
- 手感没被牺牲：4°→0、19°→0.569、41°→1.0；起振延迟 200ms
- 单帧尖峰严格为 0；两帧尖峰峰值 0.005 —— **如实标注"不断言恰好为 0"**，
  因为低通的尾巴会让信号在迟滞阈值上多停几帧，声称严格为 0 是过度承诺
- `main.py --probe` 增加抖动统计：大厅阈值穿越次数（静止时必须为 0）+
  摇头原始/低通峰峰与压掉比例

## 调高左右转向 / 抬头的灵敏度（用户反馈"有一点低，稍微调高一点点"）

### 改法：只动满速，不动死区
| 旋钮 | 语义 | 处置 |
|---|---|---|
| 死区 | **噪声地板**（3px 定位抖动 = yaw 0.22） | 保持 0.24 / 0.09 不动 |
| 满速 | **增益**（死区→满速的斜率） | yaw 1.10→0.92、pitch 0.52→0.43 |

降满速 = **纯增益**：所有未饱和角度统一 +24%(yaw) / +27%(pitch)，
而 4° 微动仍输出 0.000，噪声地板完全不变。

实测（p_raw/yaw 单位相同）：
- 摇头 0.70(≈19°)：0.569 → **0.706**；0.90(≈25°)：0.784 → **0.973**
- 抬头键值 0.35：0.605 → **0.765**；按下动作键所需抬头幅度 0.27 → **0.23**
- 原地不动 / 微动：仍是 0.000；起振延迟 167ms 不变

### 连带修掉的一个真 bug（测试抓到的，不是推测）
提高俯仰增益会把**转头耦合**一起放大（实测 p_raw ≈ 0.74·yaw）：
yaw 0.85 处残余键值 0.376 **→ 0.47 > JUMP_ON 0.42**，
也就是"大幅转头会真的把动作键按下去"。→ 把俯仰置信度衰减
`PITCH_YAW_SHRINK 0.75→0.85` / `MAX 0.60→0.70`，残余回到 0.29，转头时动作键保持关，
同时轴量 0.91 不受影响（转头仍被完整尊重）。

### 新增断言（test_head 68 项，原 64）
